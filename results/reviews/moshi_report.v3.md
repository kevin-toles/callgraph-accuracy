# moshi (Kotlin) call-graph review, v3

precision 40/50; census ≈84.7% (452 wrong of 2958 in-scope); recall: 1 missed of 33 real calls; 0 non-calls

Scope: 2,958 edges in non-test `.kt` files out of 14,643 total (high 1136, medium 1028, low 782, unknown 12). The sample was stratified with seed 3033 (18 high, 16 medium, 11 low, 5 unknown) and covers 25 files in all 4 modules. Scripts: `moshi_v3_load.py`, `moshi_v3_sample.py`, `moshi_v3_edges.py`, `moshi_v3_census.py`, `moshi_v3_probe.py` in the fanout folder.

The in-scope output is almost the same as the one reviewed in v2. Compared with `moshi.v2b.json`, exactly one in-scope edge changed, and the change is a regression (StandardJsonAdapters.kt:56, see the table). The other 60 changed `.kt` edges are all in test files. The v3 differences from v2 therefore come from the stricter spec and from scripted counting, not from tool changes.

## Spec gaps (counted separately, not as errors)
- **Lambda-with-receiver** (`buildString {}`, `buildList {}`, `buildMap {}`, `apply {}`): 71 bare low `append`/`add`/`put`/`addAll` edges. The spec does not define the receiver. The 12 cases that the tool attributes to an unrelated outer type are counted wrong (pattern 3).
- **External extension functions on typed receivers** (`type.toClassName()` with `import com.squareup.kotlinpoet.ksp.toClassName`, `getVisibility`, `getDeclaredProperties`, `parameterizedBy`, `tag<…>()`): 14 edges come out as `ReceiverType#ext`, medium. The spec does not say whether these should be `T#m` or the import-qualified function.
- **Infix function calls** (`0 until n`, `a to b`, `x shl 1`, `valueEquals`): a regex finds about 113 sites (some matches may be inside string literals), and 1 of them has an edge. The spec does not say whether an infix call is a call.
- **Annotation arguments** (`ReplaceWith(...)` inside `@Deprecated`): 2 edges with an empty caller.
- **Kotlin enum constants:** the enum-constant rule is written for Java only. It has no effect here (the only main enum, `JsonReader.Token`, has no constructor arguments).
- **Kotlin smart casts** (`is ParameterizedType -> a.actualTypeArguments`): it is unclear whether these count as a "pattern binding" for typed receivers. The tool emits low, which I accepted.
