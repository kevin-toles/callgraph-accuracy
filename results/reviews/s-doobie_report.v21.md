## Spec gaps (counted separately; scripted: `s-doobie_r21_gaps.py`)
1. **1299 + 156: case-class application.** Scanned case classes written without `new`, as in `FF.liftF(Uncancelable(body))` and `ColumnTypeError(n + 1, get, n1, p)`, are emitted as `T#<init>`, constructor, high. External case classes (`Kleisli { … }` 75, `Some(x)` 48, `NonEmptyList(a, as)` 14, `Left`/`Right` 13, `Ior.Both/Left/Right` 3, `Tuple8`, `OptionT`, `EitherT`) are emitted as `X#apply`, medium, method. Open question (CAPABILITIES `scala/16`): is `Point(0, 0)` on a case class a call, and if so is it `Point#<init>` or `Point#apply`, and at what tier, given that `apply` has no written definition?
2. **7: synthesized case-class `copy`.** `copy(constAttributes = constAttributes ++ attributes)` in `private final case class TracingConfigImpl` is emitted as `TracingConfigImpl#copy`, medium, and listed as a node. Open question: is a call of a compiler-synthesized case-class member (`copy`, `apply`, `unapply`) named by its ID, at what tier, and does it get a node although it has no written body?
3. **5: caller of code that runs in a class/trait constructor but is not a named field initializer.** The tuple-pattern val `val (xa, cleanup) = { (for { … } yield …).allocated.unsafeRunSync() }` in `class LargeRow` (large.scala 34–35) and the anonymous Scala 3 `given [A](using csv: Text[A]): Text[A *: EmptyTuple] = csv.contramap(_.head)` (TextPlatform.scala 13, 16) both get caller `Type#<init>`. Open question (CAPABILITIES `scala/17`): what is the caller of a class-body statement, a tuple-pattern val, or an anonymous given, and is there an implicit edge?
4. **43: package-object members.** `package object util { def arraySequence … ; val unlabeled … }` gives functions the Kotlin-style ID `org.typelevel.doobie.util.arraySequence`, while the field's implicit edge comes from `org.typelevel.doobie.util.package#<clinit>` to `org.typelevel.doobie.util.unlabeled`. Open question (analogous to `scala/18`): what are the IDs of Scala 2 package-object members and the caller of their initializers (`pkg.f`, `pkg.package#f`, …)?
5. **3: bare calls of a self-type member.** `fail(...)` in `trait Checker[M[_]] extends CheckerBase[M] { this: Assertions => }` (munit, scalatest) and `ko(...)` under `this: Specification =>` (specs2) are emitted as bare low names. Open question: does a self-type annotation count as an "enclosing type / inherited base" for bare-call resolution, so the callee is `Checker#fail` medium (or `munit.Assertions#fail`), or does it stay a bare low name?
6. **51: extension methods supplied by implicit conversions or syntax classes on a typed receiver.** The count is the in-scope `transact` edges alone; other syntax methods (`onError`, `as`, `bracket`, `whileM`, `queryWithAttributes` on a `Fragment`) raise the same question. Example: `naive(10000).transact(xa)` with `naive: ConnectionIO[Int]`, where `transact` comes from `ConnectionIOOps`. Open question (raised for Kotlin in GOLDEN_AUTHOR_QUESTIONS `kotlin/16`, undecided for Scala): is the callee the extension's own ID (`…syntax.ConnectionIOOps#transact`), the receiver type's `Free#transact`, or a low guess?
7. **255 in-scope occurrences, recall: string interpolators.** `sql"…"`, `fr"…"`, `show"…"`, `s"…"`, `f"…"` desugar to `StringContext(...).sql(...)` and the like, and the tool emits no edge for them. Open question: is an interpolated string a call of the interpolator method (`StringContext#s`, the doobie `SqlInterpolator#sql` extension), and with which ID, or a literal?
