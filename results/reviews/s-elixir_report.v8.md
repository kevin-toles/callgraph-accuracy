## Spec gaps (counted separately, never as wrong)
1. **G1. Calls written inside a `quote` block: 654 edges** (high 443, medium 97, low 86, unknown 28).
   - Examples: `skip(acc)` in `defmacro filter_map` (stream/reducers.ex:265), `defoverridable child_spec: 1` in `GenServer.__using__`, `Kernel.def impl_for(data) do` in `Protocol.after_defprotocol`, `unquote(target).unquote(as)(unquote_splicing(as_args))` (→ `.unquote`), `unquote(callback).(entry)` (→ callee `unquote(callback)`).
   - Open question (CAPABILITIES `elixir/12-quote-blocks`): is a call inside `quote` an edge? Is its caller the macro or the generated function? Which ID and tier does a callee get when it is defined only by the expansion, or when its receiver or name is `unquote(...)`?
2. **G3. Callers defined by `def`/`defp unquote(<non-literal>)` outside a quote: 104 edges.**
   - Examples: `defp unquote(unpad_name)(w) when band(w, unquote(mask)) == unquote(padding)` in base.ex:256 (caller `Base.unquote(unpad_name)`), and `def unquote(inspect) do` in inspect.ex:732 (caller `Inspect.Range.unquote`).
   - Open question: SPEC decides only `def unquote(:name)` with a literal name. What is the caller ID when the name is a comprehension variable or a quoted call head?
3. **G2. `defdelegate` edges: 70** (high 32, medium 38).
   - Example: `defdelegate init(opts), to: EEx.Engine` → `EEx.SmartEngine.init → EEx.Engine.init`, high, direct.
   - Open question (CAPABILITIES `elixir/18-defdelegate`): is this an edge from the generated function to the target (direct or implicit), or a declaration with no edge?
4. **G6. Locals bound to a capture literal with placeholders: 46 edges** (40 calls written inside the capture, folded into the enclosing function; 6 calls through the binding as `callback`, unknown).
   - Examples: `to_tuples = &Enum.map(&1, fn diag -> … end)` with `to_tuples.(modules_or_errors)` (kernel/parallel_compiler.ex:333/336), and `fun = &quoted_to_algebra(&1, :parens_arg, &2)` (code/formatter.ex:1681/1682).
   - Open question: is `&expr(&1, …)` a "function literal" for the named-nested-function rule (ID `outer.to_tuples`, calls high, inner calls under that caller), or a function value (callback/unknown, body folded)? SPEC lists per-language literal forms but none for Elixir.
5. **G5. Functions generated under a computed name: 19 edges**, low bare.
   - Examples: `readme_template(assigns)` in mix/tasks/new.ex:104 and `vm_args_template(release: release)` in release.ex:1329. These are generated by `embed_template(:readme, …)`, which is defined in the scanned `Mix.Generator` and builds the name `:"#{name}_template"` inside its quote.
   - Open question: the 2026-11-10 "Generated functions" ruling covers functions a scanned macro generates (`defexception`, `defdelegate`). Does it cover a name the macro computes from a literal argument, which would make it `Mix.Tasks.New.readme_template`, medium?
6. **G4. Applying a call result: 6 edges**, callback/unknown, whose callee ID is the source text of the call.
   - Example: `R.zip_with([left, right], & &1).({:cont, acc}, reduce)` → callee `R.zip_with([left, right], & &1)`. Also `Stream.resource(start_fun, next_fun, stop_fun).(acc, …)`.
   - Open question: SPEC names callbacks by "the variable's name" and computed method receivers `.member`. What is the callee ID when the applied function value is itself a call result, with no variable?
7. **R1 (recall only, no edges). Operators and control macros written as syntax** in the three recall functions: `if` ×3, `!=` ×3, `or`, `not`, `|>` ×4. The tool emits no edges for these anywhere. Explicit `Kernel.++(…)` / `Kernel.and(…)` calls do get edges.
   - Open question: are Elixir's infix operators and keyword macros (`if`, `!=`, `|>`, `not`), which are Kernel functions or macros at runtime, calls or "language constructs"?
